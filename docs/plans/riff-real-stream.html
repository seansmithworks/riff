Riff: the real stream

Project: Riff (CreativeConvos) 2026-09-13 Draft, revised after critique
What gets built

Today the canvas stays blank for 11 to 19 seconds, then every screen appears at once. After this change, pencil outlines of every screen appear first. Then each screen inks in the moment the model finishes writing it. On an edit, screens that didn't change stay exactly as they are, and only changed or new screens redraw. It's still one model call, so no extra API cost. Work happens on a new branch, feat/stream, cut from feat/voice-ui (a technical call, already made).

The gate: a ~$0.30 test before anything is built

A dev-only script calls the model 33 times across 7 test groups and times when each piece of the sketch arrives. Building starts only if all six of these hold:

  • Streaming starts fast: the first text arrives within 1.5s. This is tested with the model's hidden "thinking" left on and switched off.
  • Outlines arrive early: every screen's outline is ready within 2.5s on a new sketch and within 3s on an edit.
  • Real ink arrives early: content, not just outlines, starts within 3s. That's either screen 1 finished, or at least screen 1's first element finished.
  • Edits ink fast: on an edit, the first changed screen is finished within 5s.
  • The model admits what it changes: on "add a time-slot screen" and on "add a tab bar to every screen," it flags every screen it touches, at least as reliably as today's version makes those changes.
  • Nothing breaks: every run sends outlines before screens and ends with a valid sketch.

Cost: about $0.30 for the 33 calls, and at most about $0.75 if hidden thinking is on and every retry below runs. These are estimates.

If the test fails

  • Streaming starts slow even with thinking off: retry once without the strict JSON format. If it's still over 3s, stop and report.
  • Outlines arrive late: retry with outlines that carry only screen names. If they're still late, stop and bring Sean the measured time.
  • Outlines come after screens: add an ordering instruction and retry. If they still come after, stop.
  • No real content within 3s, whole screen or single element: stop. A ~2s ink target isn't reachable on this model.
  • Edits miss their times while new sketches pass: pause and show Sean the numbers (decision 3).
  • Change-flagging is unreliable: build the safer version instead. The model rewrites every screen and code detects which ones changed. Only changed screens still redraw, but edits lose the speed boost.

Decisions for Sean

  1. Ink one screen at a time, or one element at a time? Decide after the test, using measured numbers. Recommended: per screen if screen 1 finishes within 3s. Per element if it takes longer, since per element puts real content up at about 2.5s instead of about 5s (estimated).
  2. Pencil and ink look. Recommended: take the strawman (pencil in the kit's light border gray #d4d4d8, 280ms strokes, 35ms stagger, changed screens under a 40% white wash until they redraw) and mark it up on the first recording.
  3. Edits slower than the gate but new sketches fine. Recommended: build anyway. Screens arriving one by one still beats today's 35s wait with nothing on screen.

One new sketch, second by second

Outline and ink are different moments. The outline is empty pencil frames. Ink is real content. The test times both.

Base branch, risks, out of scope, assumptions, key findings

Base branch (technical call)

  • Every client file the stream edits was already changed on voice-ui: useVoice.ts, WireframeCanvas.tsx, ArtifactCanvas.tsx, CopilotPanel.tsx, page.tsx (git diff --stat feat/voice-lab feat/voice-ui). Building anywhere else would conflict in exactly those files.
  • The pipeline files are identical on all branches: generate.ts, artifact.ts, store.ts, route.ts and Sketch.tsx are absent from both diffs.
  • Voice-lab contributes no importable code: its draw-in is Canvas2D (build.ts:479-515@L), and its steady pen needs arrival times in advance (stream.ts:57-62@L).
  • Sync state: voice-ui is 2 behind and 10 ahead of origin/main (e39b54f). The two missing commits (51051bf, e39b54f) touch only HackathonFootnote.tsx, which voice-ui doesn't touch. Voice-lab's tip is 7fbb78d, 0 behind and 49 ahead of origin/main. The refuter measured this after a fetch; I re-counted the local refs without fetching and they match.

Risks

  • Abort may not reach Fireworks: superseded streams would bill to completion, which is today's behavior anyway (useVoice.ts:156-167@U). Step 3 detects it.
  • Hidden reasoning: it may delay first content even with json_schema. R1b isolates it.
  • The prompt-only fallback allows invalid JSON: the tracker emits only objects that parse, and generateArtifact's repair runs at done.
  • Evolve mid-stream carries removed screens: the base keeps retained-removed screens appended, and the model may keep one the user dropped. Removals apply only on done.
  • The agent may call faster than head arrives: it's told to call on every fact (create-agent.mjs:48@U). If calls come faster than about 2s, nothing inks. Flag it if seen in the live voice test; don't add a debounce unprompted.
  • Per-element partial bodies: on changed screens, the old body has to clear when the first new element lands, or old and new mix.
  • CopilotKit may still re-call: its LLM can ignore the superseded string. Step 6 counts re-calls.
  • Doubled drawably strokes (Sketch.tsx:16-24@U) may dash oddly across their two subpaths. Checked by 5(e).
  • Production: streaming on Vercel is untested, because previews have no keys.
  • Pre-existing, not fixed here: CopilotKit's AI_MissingToolResultsError on a failed generate (BACKLOG.md:66@L).

Out of scope

  • Other options: C fan-out, D pencil guesses and E edit-ops.
  • Voice sync: sendContextualUpdate narration.
  • Steady pen: it would need an arrival estimator.
  • Lab visuals in the real app: sparks, dot-grid, glow and Morph (Phases 1 to 3).
  • Progressive flows: flows render at done.
  • Skeleton: no CanvasSkeleton redesign.
  • Debounce: no debouncing of agent calls.
  • Merges and deploys: merging to main and prod deploys each need a nod.
